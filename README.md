# caerno-site — личный сайт-визитка

Статический сайт «field engagements»: пять домен-кейсов по схеме *problem → what I saw → what I built → result*, кросс-линки между кейсами — по общим методам (это и есть FDE-тезис: одни методы в несовместимых доменах).

Билдер и CSS унаследованы от `polit-linkedin` (бумага + чертёж + типографика, ноль зависимостей, без JS). Бэклог и решения — в вольте: `stuff/Projects/Сайт-визитка/00_бэклог.md`. Канон фактов — `stuff/Personal/Резюме 2026.md`; сюда факты попадают только калиброванными (никакого «high-load», никаких метрик объёма кода).

## Сборка

```bash
node build.mjs   # data/ -> dist/
./serve.sh       # + локальный сервер на :8138
```

`data/profile.json` — хиро и ссылки. `data/cases/<slug>.json` — по кейсу на файл; порядок подачи — `ORDER` в `build.mjs`; реестр методов — `METHODS` там же. `data/roles.json` — двенадцать кресел экипажа (см. ниже).

## Двенадцать кресел (`crew.html`)

Второй вход на сайт: карта оргструктуры небольшой команды, делающей продукт с LLM. Пять
основных кресел, семь вспомогательных; по каждому — что держит, чем измеряется, что ломается
пока оно пустое, грейд-бенд, **покрытие** (`covered` / `partial` / `uncovered`), доказательства
со ссылками на кейсы, строка «где я останавливаюсь» и комплиментарное кресло.

Страница читается двумя способами: основателю — карта (полезна и без меня), нанимателю — резюме
по значкам покрытия. Второе не портит первое ровно потому, что нагрузка — **данные** (значок +
ссылка), а не проза о себе. Правило: про себя можно писать только в полях `evidence` и `limit`.
Разбор — в вольте, `Projects/Сайт-визитка/02_ростер-и-окна.md`.

### Оконный слой

Карточки кресел открываются как перетаскиваемые окна поверх страницы. Четыре правила, которые
держат это в ~120 строках ванильного JS вместо фреймворка:

1. одно состояние на страницу — массив `open` (что открыто, в порядке открытия);
2. URL хранит **что** открыто (`#win=judge,envoy`), никогда — где окно стоит; перетаскивание в историю не пишет. Читается в обе стороны: `hashchange`/`popstate` приводят набор окон к тому, что написано в адресе;
3. содержимое окон лежит в `<template data-win="…">` на самой странице — ни `fetch`, ни состояний загрузки;
4. один делегированный обработчик на документ, поведение через `data-open` / `data-close`; новое окно = новая строка в JSON.

Карточка — настоящая `<a>` на настоящую страницу `crew-<id>.html`: без JS, на экране уже 720px
и для краулера это обычная навигация. Окна — улучшение, а не механизм доставки контента.

## Динамическая упаковка (линзы)

`data/packagings.json` — линзы (роль/тезис/лид/featured-кейсы). Автоплей после ревью 27.07: крутятся только роль+тезис (8 с, пауза по hover); лид и карточки меняются только кликом. Клик фиксирует линзу и пишет `#as=<id>` в URL — прицельные ссылки под вакансию: `#as=sa`, `#as=ai`, `#as=cto`.
